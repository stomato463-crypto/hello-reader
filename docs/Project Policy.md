# Project Policy (プロジェクトポリシー)

本プロジェクト（Hello Reader）は、Debian / GNU Linux のオープンソース精神（ボランティア主義・相互リスペクト・開発者の自由）を尊重し、以下の基本方針に基づいて運営されます。

---

## 1. ボランティア主義と持続可能性 (Voluntary Basis & Sustainability)

* 本プロジェクトは完全なボランティアベースで運営されています。
* 開発者（ maintainer ）の心身の健康、プライベートな生活の平穏、およびマイペースな開発の持続可能性を第一優先とします。

## 2. ベストエフォート型のサポート (Best-Effort Support)

* ユーザーからのバグ報告や改善のご提案、アクセシビリティに関するフィードバックは温かく歓迎します。
* ただし、個別の動作サポート、質問への即時回答、および特定機能・不具合修正の「法的・道義的な義務」は負いません。
* すべての対応は開発者が可能な範囲（ベストエフォート）において、無理のないペースで順次行います。

## 3. アクセシビリティと自由の尊重 (Accessibility & Freedom)

* 本ソフトウェアは、視覚障害・盲ろうを含むすべてのユーザーのアクセシビリティ向上を目的として開発されています。
* ライセンス（BSD Clear License）に従い、誰もが自由に使用・研究・改変・再配布することができます。

## 4. プライバシーと安全な境界線 (Privacy & Boundaries)

* 開発者の個人電話番号やプライベートな連絡先は非公開とします。
* サポートや問い合わせは、アプリ内に用意された匿名診断ログ機能や、指定された安全な窓口（GitHub Issue等）を通じてのみ受け付けます。

## 5. コード貢献方法 (How to Contribute)

本プロジェクトへの貢献は、以下のどちらの方法でも大歓迎します。

### 方法 A: Pull Request (PR)

* **Web画面から作成**: GitHub の Web 画面から Fork / Branch し、プルリクエストを作成してください。
* **GitHub CLI (`gh`) コマンドで作成 (CLI派向け)**:

  ```bash
  # ブランチを作成して push した後、gh コマンドでPRを作成できます
  gh pr create --title "fix: 変更タイトル" --body "変更内容の説明"
  ```

### 方法 B: パッチリクエスト (.patch ファイル送信)

* CLI やテキスト環境を好む方、スクリーンリーダーでコード差分を確認したい方向けに、`git format-patch` によるパッチ送信を歓迎します。

#### 💡 パッチファイルの作り方と送信手順

1. **変更をコミットする**

   ```bash
   git add .
   git commit -v -m "fix: ここに変更内容を書く"
   ```

2. **パッチファイル (.patch) を作成する**

   ```bash
   git format-patch -1
   ```

   ※ 直近1回分のコミットから `.patch` ファイル（例: `0001-fix-....patch`）が生成されます。
3. **パッチ（.patch）を開発者（メンテナ）へ届ける方法**
   作成した `.patch` ファイルは、以下のいずれかの方法で送ってください：
   * **【おすすめ CLI】GitHub CLI (`gh`) コマンドで一発送信 (ターミナル派向け)**:

     ```bash
     # gh コマンドでパッチファイルをそのまま本文にして Issue を作成！
     gh issue create --title "fix: 修正パッチ提案" --body-file 0001-fix-xxxx.patch

     # （または gh gist コマンドでパッチを Gist 化して URL を共有）
     gh gist create 0001-fix-xxxx.patch
     ```

   * **GitHub Issue や Discussion に添付・貼り付け**:
     新規 Issue やコメント欄の「Attach files」ボタン（参照・ファイル選択ダイアログ）から `.patch` ファイルを選択して添付、またはパッチ本文のテキストをコピーしてコメント欄（```diff ...```）に直接貼り付けて送信。
   * **メール・サポート窓口に添付**:
     アプリ内の SOS サポート窓口や問い合わせメールに `.patch` ファイルを添付して送信。

#### 🛠️ 受け取ったパッチの適用方法 (メンテナ側)

届いた `.patch` ファイルをローカルリポジトリに取り込む場合は、以下のコマンドで一発適用できます：

```bash
# パッチを適用して自動コミットする (推奨)
git am < 0001-fix-....patch

# （または差分のみをテスト適用する）
git apply 0001-fix-....patch
```
