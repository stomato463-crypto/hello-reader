## AIエージェントの役割

- AIはAndroid AccessibilityServiceスクリーンリーダーを安全かつクリーンに開発するのを支援する。

## コードについて

- スクリーンリーダー計画書（リポジトリ内）に基づいて、Android標準アクセシビリティガイドラインに準拠し、Nullポイントエラーを回避する。
  kotlinの最新ステーブルバージョンに追随して記述する。
  APKの最適化（アラインメントやほかの細かい内容は、Androidデベロッパーガイドライン（最新版）にしたがって行う。
  スクリーンリーダーとして必須な権限も、同様とする。

### ビルドスクリプトについて

- ビルドスクリプトや、adbでアクセシビリティーを有効化するスクリプト、デバイスにデプロイするためのスクリプトを./toolsに作成する。
  なお、ユーザー名や必要なツールなどは、クロスプラットフォームにするため、OSの環境変数から取得するようにする。

## ビルドスクリプトの内容

 出来上がったAPKは、リポジトリの中に、androidデベロッパーガイドラインに従って、適切な場所に出力する。
  また、OSのユーザーのデスクトップにも、hello-readerというフォルダの中にコピーする。
  ファイル名は、debug/releaseの後に、-で区切って、gitのコミットハッシュ値の先頭8文字、日付-時間.apkとする。

## 🌸 なでしこを活用した仕様書の作成 ＆ 柔軟な対話スタイル

- `./src/*.nako3` 配下に配置された日本語プログラミング言語「なでしこ3」形式のファイルを、本プロジェクトの公式仕様書（設計図）として使用する。
- AIは `./src/*.nako3` に記述された直感的な日本語ロジック（「もし〜違えば〜ここまで」等）を理解し、Android ガイドラインに準拠した Kotlin コードの実装・修正を行うこと。
- AIは、ユーザーさんや参加する開発者の希望スタイルに合わせて、なでしこ言語（日本語表現）での提案や、Kotlinなどそれぞれの望む方法で対話・提案をフレキシブルに行うこと。

## ⚙️ コマンド＆Gitポリシー

### コマンド実行の制限

- AIはビルドコマンド（例: `.\build_apk.ps1` や `gradlew assembleDebug`）を直接実行してはならない。必ずチャット上で正確なコマンドを提示し、ユーザーさんにコピーして実行してもらうこと。
- AIはデプロイ、インストール、ADBコマンドを直接実行してはならない。チャット上でコマンドを提案し、ユーザーさんにコピーして実行してもらうこと。

## commitメッセージの生成

AIは、commitメッセージを簡潔でわかる英語で作成し、必ず、git commitコマンドも提示し、ユーザーさんに実行してもらうこと

### 📢 コマンド提示時の詳細表示（-v / --verbose）ポリシー

- ユーザーさんがコマンドを実行した際、処理経過や実行結果をしっかり視覚・スクリーンリーダーで確認できるよう、詳細表示オプション（`-v` / `--verbose`）が使えるコマンド（例: `rm -v`, `mkdir -v`, `cp -v`, `mv -v`, `curl -v`, `tar -v`, `keytool -v`, `git commit -v`, `git push -v` など）を提案する場合は、優先して `-v` や `--verbose` フラグを付けてチャット上に提示すること。

### Git操作の制限

- AIはブランチ切り替えコマンド（例: `git switch`, `git checkout`）のみ、正しいブランチで作業するために直接実行してもよい。
- AIはそれ以外の変更を伴うGitコマンド（例: `git commit`, `git push`, `git merge`, `git pull`）を直接実行してはならない。必ず実行すべきGitコマンドをチャット上に提示し、ユーザーさんにコピーして手動で実行してもらうこと。
