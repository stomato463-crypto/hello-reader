# hello-reader specification guidelines

## このプロジェクトについて

- 「なでしこ3」は、日本語でプログラムを書ける日本語プログラミング言語「なでしこ」の現行版です。
- 公式サイト: [なでしこ公式サイト](https://nadesi.com/)
- このプロジェクトでは、なでしこ3のGo言語版である `gonako` でhello-readerのためのわかりやすい仕様書を作成します。ブラウザ版やNode.js版だけの命令があるため、利用できる命令は必ず `gonako doc` で確認してください。
- 詳しい文法: [なでしこ3 文法](https://github.com/kujirahand/nadesiko3/blob/master/doc/syntax-nako3.md)

## 応答と言語

- AIは日本語で応答してください。
- もし日本語以外で話しかけられた場合には、その言語で応答してください。
- 仕様書はUTF-8のなでしこ3ファイル（拡張子: `.nako3`）として作成してください。
- なでしこ3は日本語で記述しますが、自由な自然言語ではありません。以下の文法、実在する命令名、命令ごとに決められた助詞を守ってください。

## 命令とマニュアルの調べ方

コードを書く前に、利用する命令の名前、書式、助詞を検索してください。意味から命令名や助詞を推測しないでください。

```powershell
gonako doc キーワード            # 組み込みの命令一覧を検索
gonako doc キーワード --json     # AIが読みやすいJSON形式
gonako doc キーワード --web      # Webのマニュアルも検索
```

複数の語はAND検索になります。検索結果に命令がなければ、別のキーワードで検索するか、実現方法を見直してください。

## 基本文法

### 文、コメント、値

- 文は改行または `。` で区切ります。
- 行コメントは `#`、範囲コメントは `/*` と `*/` を使います。
- 数値は `123`、真偽値は `真` と `偽` です。
- `「...」` と `"..."` は `{変数名}` を展開します。`『...』` と `'...'` は展開しません。
- 四則演算は `+ - * / %`、比較は `= == != > < >= <=`、論理演算は `かつ` と `または` を使えます。複雑な式は丸括弧で囲んでください。

```nako3
名前は「なでしこ」
年齢=3
「{名前}{年齢}です」と表示
```

### 変数、配列、辞書

- 代入は `答は0` または `答=0` と書きます。
- 配列は `[10,20,30]`、辞書は `{"名前":"なでしこ","年齢":3}` と書きます。
- 配列の添字は0から始まります。要素の参照と代入には `一覧[0]`、辞書には `人物["名前"]` を使います。`一覧@0` の形式でも参照できます。
- 変数名に助詞を含めないでください。命令名と同じ変数名も避けてください。

```nako3
一覧=[10,20,30]
人物={"名前":"なでしこ","年齢":3}
一覧[0]=99
「{人物["名前"]}: {一覧[0]}」と表示
```

### 命令、助詞、連文

- 命令は原則として `引数＋助詞＋命令名` の順です。例えば `「こんにちは」と表示` と書きます。
- 助詞は単なる飾りではなく、引数の割り当てに使われます。`gonako doc` の検索結果に記載された助詞だけを使ってください。
- 命令の結果は特殊変数 `それ` に入ります。
- `AしてB` という連文では、Aの戻り値がBの最初の引数に渡ります。例えば `3に5を足して表示` は、加算結果を表示します。

### 条件分岐とブロック

- 複数行のブロックは、行末に `:` を付け、次の行を半角空白でインデントする書式を推奨します。`:` の直後には必ず改行してください。
- `:` を使わない場合は、ブロックの最後に `ここまで` が必要です。
- 等しいかの判定には `=` または `==` を使います。代入と混同しないよう、条件式を丸括弧で囲んでください。

```nako3
もし、(年齢>=18)ならば:
  「成人です」と表示
違えば:
  「未成年です」と表示
```

### 繰り返し

- `N回:` では、現在の回数を `回数` で参照できます。
- `Iで1から10まで繰り返す:` の範囲には、開始値と終了値の両方を含みます。
- `要素で一覧を反復:` で各要素を処理できます。変数名を省略した場合、現在の要素は `対象` に入ります。
- `条件の間:` で、条件が真の間だけ繰り返します。

```nako3
答=0
Iで1から10まで繰り返す:
  答=答+I
「合計は{答}です」と表示
```

### ユーザー定義関数

- 引数は `変数名＋助詞` で定義します。呼び出すときも同じ助詞を使ってください。
- `関数` の別名として `●` を使えます。
- 値は `値を戻す` または `値で戻る` で返します。
- 標準命令と見分けやすくするため、ユーザー定義関数名の末尾には「処理」を付けることを推奨します。

```nako3
●(AとBの)加算処理とは:
  A+Bを戻す

答=3と5の加算処理
答を表示
```

## 作成後の確認

- 作成・修正したプログラムは必ずNullエラーがないかチェックし、期待する結果になることを確認してください。
- エラーになった場合は、エラーメッセージを読んでから `gonako doc` で命令名・書式・助詞を再確認し、修正とチェックを繰り返してください。
- コマンドラインでの検証には `gonako lint 仕様書.nako3` を使用してください。

## gonako lint 通過・エラー回避のための重要ポイント

1. **関数からの途中脱出・制御**
   - `処理を終了` は未定義単語エラーになります。関数の途中終了・復帰には **`戻る`** または **`戻る。`** を使用してください。
   - ループ（反復）の継続には **`続ける`** を使用してください。

2. **未定義の動詞（Android操作・仕様メモ記述）の扱い**
   - なでしこ3の組み込み命令にない動詞（例: `音声を即時中断`、`フォーカス音を再生`、`インテントを起動` など）を直接書くと、「未解決の単語」エラーになります。
   - アクションや補足説明メモは、必ずコメント `# - 音声を即時中断` にするか、標準命令 `表示`（例: `「〜」を表示`）として記述してください。

3. **配列への要素追加**
   - 動的配列への追加には `項目リスト[要素数(項目リスト)] = 要素` の形式を使用してください。

4. **コメント記号の厳格な記述**
   - 1行目のタイトルや概要等で `/ メモ /` のように単一のスラッシュで囲むと構文エラーになります。
   - 必ず行コメント `#` またはブロックコメント `/* ... */` を正しく使用してください。

5. **Kotlin実装化時の完全なインポート文チェック**
   - `.nako3` 仕様書から Kotlin コードを作成・更新する際は、`AccessibilityService` や `WindowManager` など利用するすべての Android システムクラスの `import` 文漏れが発生しないよう厳格にチェック・自動補完すること。
